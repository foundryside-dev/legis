# PDR-0010 — 1.4.0 dependency-security scope: bring in the starlette fix, defer the esbuild advisory

Date: 2026-06-29   Status: accepted (within grant — a delivery/dependency-scoping call; the publish carrying it was owner-authorized under [[0009-ship-legis-1.4.0-consolidated-release]])   Author: claude (opus, product-owner)
Supersedes: —   Related: [[0009-ship-legis-1.4.0-consolidated-release]]; GHSA-82w8-qh3p-5jfq + GHSA-jp82-jpqv-5vv3 (starlette); GHSA-g7r4-m6w7-qqqr (esbuild); tracker legis-70658a5bbc (esbuild follow-up)

## Context
While cutting 1.4.0, Dependabot flagged **3 alerts on the default branch (1 high, 2 low)**. The release had to decide which to bring in.

## Options considered
- **starlette** — HIGH `request.form()` DoS (GHSA-82w8-qh3p-5jfq) + LOW `request.url.hostname` poisoning (GHSA-jp82-jpqv-5vv3), both fixed in 1.3.1; a **runtime** dep of the legis wheel via `fastapi>=0.115`. Bring in vs defer.
- **esbuild** — LOW arbitrary-file-read on a **Windows dev server** (GHSA-g7r4-m6w7-qqqr, npm), a **transitive** dep in `site/` (the docs site, NOT the legis wheel). Bring in vs defer.

## The call
**Bring in starlette (1.2.1 → 1.3.1); defer esbuild.** fastapi requires only `starlette>=0.46.0` (open upper bound), so `uv lock` resolved the bump with the lockfile as the *only* change, and it passed the full gate battery — low-risk, fixes a HIGH runtime vuln → ship it. esbuild is out-of-package (site/ only, not shipped in the wheel) and **capped by its parents' `^0.27` ranges below the 0.28.1 fix**, so it cannot be bumped in isolation (why Dependabot opened no PR); fixing it needs parent bumps or an npm override + a full site rebuild to verify → not low-risk, negligible impact (LOW, Windows-dev-only, site builds on Linux CI) → defer to a separate site-only change (**legis-70658a5bbc**).

## Rationale
Ship security fixes that are **low-risk *and* in-scope**; do not force a risky transitive bump for a negligible, out-of-package advisory into a release. The starlette bump is test-gated and touches only the lockfile; the esbuild fix is unverifiable without the npm toolchain and would disrupt the site's build discipline for near-zero security benefit. Deferring it is recorded and tracked, not dropped — the dependabot alert stays open on the default branch until the site-only change lands, which is honest.

## Reversal trigger
- If **starlette 1.3.x** is found to break the HTTP API surface in the field → pin/revert the bump.
- If the **esbuild advisory escalates** in severity, or the docs-site's dev server becomes a real exposure (e.g. hosted/CI dev-server, non-Linux build) → prioritize the parent-package bump / npm override (legis-70658a5bbc).
